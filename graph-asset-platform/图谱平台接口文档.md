# 图谱平台接口文档

> 图谱资产管理平台为 Agent 同时提供 **MCP 服务**（`/mcp`，4 个公开工具：
> `get_domains` / `search_graph` / `search_files` / `get_md`）和 **REST 兼容接口**
> （`POST /api/v1/domains`、`POST /api/v1/md`、`POST /api/v1/search`、
> `POST /api/v1/files`，与 MCP 共用同一业务实现）。两条通道使用同名的工号/会话字段并自动打点；
> 统计查询仍走 REST（详见 §3）。
>
> 2026-09-08 三工具重构：搜索收敛为 `search_graph`（terms + any/all 统一搜
> 元数据与正文）；旧工具 `search_objects` / `search_md` / `get_object` 已隐藏
> 兼容（deprecated，仍可直调，见 §2.6）。
> 2026-09-09：搜索补 REST 通道 `POST /api/v1/search`（与 MCP `search_graph`
> 完全同契约）。
> 2026-09-29：新增 `search_files`（文件名搜索/目录浏览，find/ls 语义，MCP 与
> REST `POST /api/v1/files` 同构，见 §2.4）；同批超时治理——`search_graph` 改
> **有界候选池**（触顶置 `total_is_bounded`，不再报 `SEARCH_TOO_BROAD`），短词
> 两档可降级（§2.3）。


## 兼容接口（REST，2026-09-03 恢复，与 MCP 并行）

为兼容 Agent/SKILL 配置，保留 REST 接口；权限与 MCP 一致（skill：
`can_skill` 或 `can_frontend`，admin 全权），鉴权同样走 `X-API-Key` 请求头。
打点与 MCP 行在运维页「知识取用频次」合并计数。**两条通道业务数据、护栏、
错误完全一致**（同一核心实现）——四个 MCP 公开工具各有一个 REST 同构端点。

四个 REST POST 的 JSON body 都必须传与 MCP 工具完全同名的归因字段：
`AGENT_USERNAME`（工号）和 `AGENT_SESSION_ID`（会话 ID）。它们分别写入
telemetry 的 `operator` / `session_id` 专列，不重复写入调用参数 `params`。
`user` 仍取 `X-API-Key` 的属主账号。服务会去除两个值的首尾空白，拒绝空值；
工号最长 64 字符，会话 ID 最长 128 字符。**未知字段会被拒绝**（422，防拼错
被静默忽略）。二者是调用方声明的统计归因元数据，不参与鉴权。

| 接口 | 请求 | 响应 |
|---|---|---|
| `POST /api/v1/domains` | `{"AGENT_USERNAME":"工号","AGENT_SESSION_ID":"会话ID"}` | `[DomainItem, ...]`（见 §2.1；与 MCP `get_domains` 的 `domains` 数组内容完全相同，仅外层无包装） |
| `POST /api/v1/md` | `{"ids":["ID",...],"version":"可选","AGENT_USERNAME":"工号","AGENT_SESSION_ID":"会话ID"}` | `{id: MdSuccess \| MdFailure}`（见 §2.2；与 MCP `get_md` 完全相同） |
| `POST /api/v1/search` | `{"terms":["关键词",...],"match":"any可选","layer/type/nf/version/domain/scenario":"可选过滤","page/size":"可选","AGENT_USERNAME":"工号","AGENT_SESSION_ID":"会话ID"}` | `SearchGraphResponse`（见 §2.3；与 MCP `search_graph` 完全相同） |
| `POST /api/v1/files` | `{"query/path/ext":"可选(至少一个)","recursive":false,"limit":100,"after":"可选游标","AGENT_USERNAME":"工号","AGENT_SESSION_ID":"会话ID"}` | `SearchFilesResponse`（见 §2.4；与 MCP `search_files` 完全相同） |

**REST 错误体（四接口固定）**：`HTTP <status>` + `{"error": {code, message,
retryable, details}}`。401 `UNAUTHENTICATED` / 403 `PERMISSION_DENIED` /
422 `INVALID_ARGUMENT`（缺归因、未知字段、枚举/越界参数）/ 422
`INVALID_FILTER` / `INVALID_FILTER_COMBINATION`（带 `available_values`）/
413 `RESULT_TOO_LARGE`（响应超 2MB）/ 413 `SEARCH_TOO_BROAD`（**已退场
deprecated-unused**，2026-09-29 超时治理后不再触发，码位保留兼容）/ 503
`INDEX_REBUILDING`（retryable=true，稍等重试）/ 500
`INTERNAL_ERROR`（只给通用消息）。`get_md` 的对象不存在/版本不存在是
**单项失败**（200 响应内该 id 的 `ok:false` 条目），不是 HTTP 错误。

```bash
curl -s -X POST http://127.0.0.1:8000/api/v1/domains -H "X-API-Key: $GRAPH_API_KEY" -H "Content-Type: application/json" -d "{\"AGENT_USERNAME\":\"${_AGENT_USERNAME}\",\"AGENT_SESSION_ID\":\"${_AGENT_SESSION_ID}\"}"
curl -s -X POST http://127.0.0.1:8000/api/v1/md -H "X-API-Key: $GRAPH_API_KEY" -H "Content-Type: application/json" -d "{\"ids\":[\"NetworkScenario@charging\"],\"AGENT_USERNAME\":\"${_AGENT_USERNAME}\",\"AGENT_SESSION_ID\":\"${_AGENT_SESSION_ID}\"}"
curl -s -X POST http://127.0.0.1:8000/api/v1/search -H "X-API-Key: $GRAPH_API_KEY" -H "Content-Type: application/json" -d "{\"terms\":[\"计费欺诈\",\"免费RG\"],\"AGENT_USERNAME\":\"${_AGENT_USERNAME}\",\"AGENT_SESSION_ID\":\"${_AGENT_SESSION_ID}\"}"
curl -s -X POST http://127.0.0.1:8000/api/v1/files -H "X-API-Key: $GRAPH_API_KEY" -H "Content-Type: application/json" -d "{\"path\":\"Command/UDG\",\"AGENT_USERNAME\":\"${_AGENT_USERNAME}\",\"AGENT_SESSION_ID\":\"${_AGENT_SESSION_ID}\"}"
```

## 概述

| 能力 | 通道 | 用途 |
|---|---|---|
| 全部业务域 md | MCP `get_domains` / REST `POST /domains` | 入口定位（一次性全部域） |
| **统一搜索**（元数据+正文） | MCP `search_graph` / REST `POST /search` | 不知道 ID 时定位候选（多关键词 terms + any/all） |
| **文件名搜索 / 目录浏览** | MCP `search_files` / REST `POST /files` | 按文件名找文件 / 列目录（find/ls 语义，**不搜内容**）；md 命中回带 `obj_id`+`version` 直通 `get_md` |
| 批量取对象 md | MCP `get_md` / REST `POST /md` | 全程主力（沿 `references`/`[[ID]]` 引用逐层下钻）；**权威原文唯一来源** |
| 打点统计 | REST `GET /api/v1/telemetry/stats` | 取用频次聚合（只读，详见 §3） |
| 底表导出 | REST `GET /api/v1/telemetry/skill-usage` | 调用级/对象级明细批量导出（scope） |

**核心调用路径**：

```text
业务方案定位：get_domains → get_md
不知道 ID（按内容找对象）：search_graph → get_md
按文件名找文件 / 列目录：search_files →（md 命中）get_md
已经知道 ID：get_md
```

## 1. MCP 服务接入

### 1.1 端点与鉴权

- **URL**：`http://<平台地址>:<端口>/mcp`（Streamable HTTP，stateless + JSON 响应）
- **鉴权**：唯一凭证 `X-API-Key` header（管理员自定义或系统生成，≥8 位无空格，无前缀要求），要求 `skill` 权限（can_skill / can_frontend / admin 任一）。无 KEY/错 KEY → HTTP 401；无权限 → 403。
- **完整接入配置**（KEY 获取、Claude Code / Cursor / 云 Agent 配置、系统提示词模板、验证排障）：见 [docs/MCP配置指南.md](docs/MCP配置指南.md)。

### 1.2 客户端配置（以 Claude Code `.mcp.json` 为例）

```json
{
  "mcpServers": {
    "graph": {
      "type": "http",
      "url": "http://127.0.0.1:8000/mcp",
      "headers": { "X-API-Key": "sk-xxxxxxxxxx" }
    }
  }
}
```

> 云 Agent 平台在平台级配置一次 KEY 即可（所有用户共用连接）；用户身份不走 header（见 §1.3）。

### 1.3 上下文参数（用户身份，每次工具调用必传）

云 Agent 场景下不同用户的工号/会话ID不同，无法静态配 header——**随每次工具调用传参**，Agent 从沙箱环境变量读取：

| 工具参数 | 沙箱环境变量 | 用途 |
|---|---|---|
| `AGENT_USERNAME` | `_AGENT_USERNAME` | 用户工号 → 打点 `operator`（追溯"谁在用"） |
| `AGENT_SESSION_ID` | `_AGENT_SESSION_ID` | 会话ID → 打点 `session_id`（会话维度统计） |

> 两个参数在全部 4 个公开工具上都是必填；仅用于打点归因，**不影响调用结果**。
> 服务会去除首尾空白并拒绝空值；工号最长 64 字符，会话 ID 最长 128 字符。
> **未知参数会被拒绝**（INVALID_ARGUMENT）——schema 即契约（`additionalProperties: false`）。

### 1.4 管理员工具配置（visibility 三态，2026-09-08）

admin 可在前端「MCP 工具」页（或 `GET/PATCH /api/v1/mcp-tools`）配置每个工具：

- **visibility 三态**：`visible`（tools/list 展示 + 可调）/ `hidden`（不展示 +
  可直调——兼容已缓存旧 schema 的客户端）/ `disabled`（不展示 + `TOOL_DISABLED`）；
- **补充说明**（supplemental_description）：**追加**在 canonical 描述之后，
  不能覆盖接口契约（schema/错误码/调用纪律由代码固定）；
- **服务总体说明**：同样只追加在 canonical 决策树之后。

配置全局生效、保存即生效、重启自动恢复。详见 [docs/MCP配置指南.md](docs/MCP配置指南.md) §7。

## 2. MCP 工具明细

### 2.1 `get_domains` — 全部业务域

- **参数**：仅 §1.3 上下文参数
- **返回**：`{"domains": [DomainItem, ...]}`——按 id 升序，每个域最新版本。

**DomainItem**（6 字段，REST `/domains` 返回同内容裸数组）：

```json
{
  "id": "BusinessDomain@business-awareness",
  "type": "BusinessDomain",
  "name": "业务感知",
  "version": null,
  "md": "完整 markdown（frontmatter + 正文 + ## 边段）",
  "references": ["NetworkScenario@charging"]
}
```

`references` 从完整 md 全文提取的 `[[ID]]` 引用（去重保序）——直接给出下钻入口。

### 2.2 `get_md` — 批量取对象 md（主力，权威原文唯一来源）

- **参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ids` | string[] | 是 | 1~**100** 个对象逻辑 ID（建议每批 5~20；重复自动去重保序，key=trim 后规范 ID） |
| `version` | string | 否 | 全局版本；不传 → 每个 id 各取**最新现存版本**；某 id 不在该版本 → 该 id 计错回带 `available_versions`，**不影响其余 id** |

- **返回**：`{id: MdSuccess | MdFailure}`——每个 id 恰好一个条目。

**MdSuccess**（ok=true）：

```json
{
  "ok": true, "id": "UDG@MMLCommand@ADD URR", "type": "MMLCommand",
  "name": "ADD URR", "nf": "UDG", "domain": null, "scenario": null,
  "version": "20.16.0", "versions": ["20.15.2", "20.16.0"],
  "md": "完整 markdown",
  "references": ["UDG@ConfigObject@URR"]
}
```

**MdFailure**（ok=false，单项失败不阻断整批）：

```json
{"ok": false, "id": "...", "error_code": "OBJECT_NOT_FOUND | VERSION_NOT_FOUND",
 "error": "对象不存在 / 版本不存在: id@ver", "requested_version": null,
 "available_versions": []}
```

> 旧字段 `version`/`md` 与 `error`/`available_versions` 保留（向后兼容扩展）；
> 无版本对象 `version=null`、`versions=[]`。**MMLCommand 参数字段范围以本工具
> 返回的 CommandParameter 段为准**——搜索摘要不能替代。

- **护栏**（REST 与 MCP 完全相同）：去重后 ids ≤100；响应总量 ≤2MB（按业务
  map 紧凑 JSON UTF-8 字节计量），超限整单失败（413 `RESULT_TOO_LARGE` /
  MCP tool error）指引分批。

### 2.3 `search_graph` — 统一搜索（元数据 + 正文）

不知道对象 ID 时的唯一入口（REST 同构端点：`POST /api/v1/search`，请求体 =
本工具参数 + 归因字段，响应/错误完全相同）。同时搜 id/name/name_zh 与 md
正文，输出候选 + 匹配原因；**snippet 不是权威依据**——选定候选后必须 `get_md`。

- **参数**：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `terms` | string[] | 必填 | 1~10 个关键词（每项 1~80 字符）。每项是**一个**字面关键词或短语：`["ADD URR"]` 是含空格的完整短语；`["计费欺诈","免费RG"]` 是两个独立词。规范化（NFKC+casefold）后去重 |
| `match` | `any`/`all` | `any` | any=任一命中（召回优先）；all=全部命中（位置可分散） |
| `layer` | 枚举 | null | 命令层/特性层/任务层/业务层；与 type 同传按**交集**（冲突报错不忽略） |
| `type` | string | null | 对象类型（如 MMLCommand）；非法值返回合法值列表 |
| `nf` | string | null | 网元（自动转大写，如 UDG）；不确定就不传，看结果 facets |
| `version` | string | null | 精确版本；不传=只搜每 ID 最新版；传旧版本可搜旧正文 |
| `domain` / `scenario` | string | null | slug 精确匹配 |
| `page` / `size` | int | 1 / 20 | size ≤50 |

- **返回**：`{terms, match, applied_filters, total, total_is_bounded, page,
  size, has_more, next_page, hits[], facets, diagnostics, suggestions}`。

**hits[]**：`{id, type, layer, name, nf, domain, scenario, version, versions[],
matched_terms[], matched_in[](id/name/name_zh/body), snippets[{term,text}](≤3),
rank_reasons[]}`——排序固定为：命中词数 ↓ → 元数据等级（id 全等>名称全等>前缀>
包含）↓ → 正文 RRF ↓ → (type, id) ↑。

**facets**：当前结果构成（分页前精确计数：layers/types/nfs/versions）。
**diagnostics**：`term_counts`（兼容旧客户端的每词整数；值为有界候选池内的
去重对象数，可继续直接做 `count > 0`）+ `term_stats`（每词 `{hit, capped}`——
`hit`=该词在候选池内是否有命中、`capped`=该词候选池是否触顶）+
`recovery_codes`（零结果时：`USE_MATCH_ANY` / `REMOVE_OR_REPHRASE_TERM` /
`RELAX_FILTERS`）+ `body_skipped_short_terms`（因长度/档位限制未搜正文的
短词回显，见下）。

- **封顶口径（与 `search_files` 的双封顶分别注意）**：
  - `search_graph` = **候选池 2000/词/来源**。≥3 字符元数据与正文均走
    trigram FTS；元数据先合并 exact → prefix → broad 三段候选，确保精确/前缀项
    不被宽包含池挤掉。宽泛词被按相关度**采样截断**，`total_is_bounded=true`
    （正常返回，不报错）；`match=all` 的交集可能不含池外命中；全量获取场景
    请改用 `search_files`（`after` 游标循环翻页）。
  - `search_files` = **计数封顶 10000**（`total` 精确到 10000，超过置
    `total_is_bounded`，见 §2.4）。
- **错误**：非法 filter 值 → `INVALID_FILTER`（带 `available_values`）；值合法
  但组合无对象 → `INVALID_FILTER_COMBINATION`——都不是静默 0 结果。命中量
  过大**不再报错**（原 `SEARCH_TOO_BROAD` 已退场 deprecated-unused，码位保留
  兼容），按相关度截断返回并置 `total_is_bounded=true`。
- **短词两档**（<3 字符，如 `N2`/`RG`，最多 3 个）：
  - 1 字符：恒只搜元数据（id/name/name_zh），跳过正文；
  - 2 字符：由平台 meta 表 `search_short_term_mode` 控制，默认 `body_like`
    档——正文走语料扫描（trigram 索引对 <3 字符模式与 ESCAPE 子句均不生效，
    实测 1M 行 ~250ms；常见词被候选池早停兜住，**罕见两字词在大正文库下是
    语料级扫描、可能慢**）。内网大规模语料下两字词超时，可由管理员切
    `metadata_only` 档（2 字词只搜元数据，跳过正文）；
  - 跳过正文的短词在 `diagnostics.body_skipped_short_terms` 回显；零结果时
    suggestions 会提示「短词未搜正文，可能是零结果主因」。

### 2.4 `search_files` — 文件名搜索 / 目录浏览（find/ls 语义）

按文件名找文件、按目录浏览资产库（REST 同构端点：`POST /api/v1/files`，请求体 =
本工具参数 + 归因字段，响应/错误完全相同）。**不搜内容**——与 `search_graph`
的分工：按内容/对象找 → `search_graph`（元数据+正文）；按文件名/路径找文件 →
本工具。覆盖 assets 下全部文件（含图片等非 md）。`query`/`path`/`ext` 至少给
一个（组合=交集）。

三个用法（与 shell 对照）：

| 用法 | 等价 shell | 说明 |
|---|---|---|
| `query='ADD URR'` | `find -name '*ADD URR*'` | 全库按文件名搜（子串、不分大小写） |
| `path='Command/UDG'` | `ls <dir>` | 列**直接子项**（含子目录行；`recursive` 默认 false） |
| `path` + `recursive=true` | `find <dir> -type f` | 递归取子树**全部文件**（仅文件行，不含目录行） |

- **参数**：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `query` | string | null | 文件名关键词（子串，不分大小写；规范化 NFKC+casefold）。如 `ADD URR` 命中 `UDG@MMLCommand@ADD URR.md`。规范化后至少 2 字符。**3 字符以上走 trigram 索引；2 字符走 name 语料扫描**（trigram 索引对 <3 字符模式不生效，大库下罕见词稍慢） |
| `path` | string | null | 目录限定（相对 assets 根、正斜杠，如 `Command/UDG`）。不传=全库；目录须真实存在（否则 `INVALID_FILTER`） |
| `ext` | string | null | 扩展名**精确**过滤（统一小写，前导 `.` 自动去掉，如 `md`/`png`） |
| `recursive` | bool | false | 仅 `path` 模式生效：true=子树全部文件；false=直接子项（含子目录行） |
| `limit` | int | 100 | 单页条数 1~500 |
| `after` | string | null | 游标 = 上一页返回的 `next_cursor`；循环传直到 `has_more=false` 拿全量 |
| `AGENT_USERNAME` / `AGENT_SESSION_ID` | — | 必填 | 见 §1.3 |

输入上限（超限 `INVALID_ARGUMENT`）：`query` 原始输入 ≤200 字符（规范化后
≤80）、`path` ≤1024、`ext` ≤64、`after` ≤1024。

- **返回**：`{files[], total, total_is_bounded, has_more, next_cursor,
  index_building, applied_filters}`。

**files[]**：`{path, name, ext, is_dir, size, mtime, obj_id, version}`——按
`path` 升序（keyset 游标的确定性排序）；**目录行** `is_dir=true`、`ext=""`、
`size=0`、`obj_id`/`version` 为 `null`（键恒在）；`mtime` 为 ISO8601 UTC。
md 文件命中回带 `obj_id`+`version`——**用 `get_md(ids=[obj_id], version=version)`
读该文件对应对象的完整内容**（不带 `version` 会取该 id 最新版，可能不是这个
文件）；非 md 文件（图片等）只有元数据。

```json
{
  "files": [
    {"path": "Command/UDG", "name": "UDG", "ext": "", "is_dir": true,
     "size": 0, "mtime": "2026-08-30T06:12:44Z", "obj_id": null, "version": null},
    {"path": "Command/UDG/20.16.0/UDG@MMLCommand@ADD URR.md",
     "name": "UDG@MMLCommand@ADD URR.md", "ext": "md", "is_dir": false,
     "size": 3512, "mtime": "2026-09-01T08:30:00Z",
     "obj_id": "UDG@MMLCommand@ADD URR", "version": "20.16.0"}
  ],
  "total": 2, "total_is_bounded": false,
  "has_more": false, "next_cursor": null,
  "index_building": false,
  "applied_filters": {"path": "Command/UDG"}
}
```

上例下钻：`get_md(ids=["UDG@MMLCommand@ADD URR"], version="20.16.0")`——
锁定读**该文件**的完整 md（权威原文）。

- **total 语义（必读）**：`total` = **从当前游标位置起的剩余条数**（翻页递减，
  非全集绝对数）。计数精确到 **10000**，超过置 `total_is_bounded=true`——
  全量遍历不要依赖 `total`，以 `has_more=false` 为准。
- **after 游标全量循环**（keyset 分页：游标=上一页最后一条 path，深翻页
  O(1)、不受并发增删的页错位影响）：

```text
第一页：after 不传
循环：  把上一页 next_cursor 作为 after 传入，直到 has_more=false
```

  全量遍历请优先用 `path` 模式（索引干净）；`query` 模式深翻页每页重扫匹配集，
  每页成本更高。
- **index_building**：`true` 表示首启文件户口册仍在后台建（结果可能不全）——
  **不是错误**，可稍后重试或联系管理员执行 `files-reindex` 重建。
- **错误**：`query`/`path`/`ext` 全空、`query` 规范化后为 1 字符或空白、任一
  输入超长、`limit` 越界、未知参数 → `INVALID_ARGUMENT`；`path` 不存在或不
  是目录 → `INVALID_FILTER`（带 `field`/`value` 回显，消息含「建册期间可能
  未建全」提示）。

### 2.5 错误模型（两通道公共）

```json
{"code": "INVALID_FILTER", "message": "未知 nf: UAC3000",
 "retryable": false, "details": {"field": "nf", "value": "UAC3000",
 "available_values": ["UDG", "UNC"]}}
```

- **REST**：`{"error": {上述对象}}` + HTTP 状态码（§兼容接口节）。
- **MCP**：HTTP 200 JSON-RPC `result.isError=true`，`content[0].text` 为
  `{"error": {...}}` JSON——Agent 按错误码决定修正或停止，不原样重试。

稳定错误码：`UNAUTHENTICATED`(401) / `PERMISSION_DENIED`(403) /
`INVALID_ARGUMENT`(422) / `RESULT_TOO_LARGE`(413) / `INTERNAL_ERROR`(500) /
`INVALID_FILTER` / `INVALID_FILTER_COMBINATION` / `OBJECT_NOT_FOUND` /
`VERSION_NOT_FOUND`（后两者在 get_md 单项内）/ `INDEX_REBUILDING`（retryable）/
`SEARCH_TOO_BROAD`（已退场 deprecated-unused，2026-09-29 超时治理后不再触发，
码位保留兼容）/ `TOOL_DISABLED`。

### 2.6 兼容工具（deprecated，hidden）

`search_objects` / `search_md` / `get_object` 不再出现在新 Agent 的 tools/list，
但已缓存旧 schema 的客户端仍可直调（输入/输出形态冻结）。打点带
`deprecated: true` + `replacement`。观测一个发布周期调用量为 0 后由管理员决定
disabled/删除；管理员可显式设 `visible` 临时回滚。**新接入不要使用**。

## 3. 打点与统计

### 3.1 打点写入：自动，无专门接口

打点直接嵌在 MCP 工具与 REST 接口里，调用方无法也无需手动打点。`record()` 吞异常（失败仅 log），绝不阻断业务。

**两级记录**（telemetry 表）：

| level | 记录时机 | 说明 |
|---|---|---|
| `tool` | 每次 MCP 工具调用或 REST `/domains`、`/md`、`/search`、`/files` 请求 | 调用级统计；REST 与 MCP 均记录业务入参/结果摘要（两侧字段对齐，仅 caller/endpoint 不同） |
| `object` | `get_md`/`POST /md` 每个成功 id、`get_domains`/`POST /domains` 每个域（护栏通过后才写） | 对象级取用明细 |

字段：`{ts, level, caller, endpoint, obj_id, obj_type, user, operator, session_id}`

- `caller`：`mcp`（MCP 通道）/ `skill`（REST 通道）/ `web`（历史行）
- `user`：KEY 属主账号名；`operator`/`session_id`：来自 MCP 工具参数或 REST JSON body 中的 `AGENT_USERNAME`/`AGENT_SESSION_ID`
- endpoint：MCP=`mcp:get_domains`/`mcp:search_graph`/`mcp:get_md`/`mcp:search_files`（legacy 行保留旧名）；REST=`/domains`、`/md`、`/search`、`/files`

### 3.2 GET /api/v1/telemetry/stats — 调用统计（只读）

**口径（调用级）**：`level=tool` 且 `caller∈{skill, mcp}` 且 `endpoint∈全暴露面
端点`（REST /md、/domains、/search + MCP get_md、get_domains、search_graph +
legacy 三端点）。一次 REST /md（不管带几个 id）= 1 次；一次 MCP 工具调用 = 1 次。
（search_files 的 `/files`、`mcp:search_files` 调用行已写入 telemetry 表，但
**不属当前统计口径**、暂不计入本聚合与 §3.3 底表导出。）

- **入参**：`GET /api/v1/telemetry/stats?days=30`（1~365 天）或 `start`/`end` 时间窗，Header `X-API-Key`
- **出参**：`{total, by_endpoint, top_users, timeline, by_user, by_operator, by_session}`

```json
{
  "total": 850,
  "by_endpoint": {"/md": 420, "mcp:get_md": 230, "mcp:search_graph": 120, "/domains": 80},
  "top_users": [{"user": "10086", "count": 600}, {"user": "10087", "count": 250}],
  "timeline": [{"date": "09-08", "count": 120, "granularity": "day"}],
  "by_user": {"agent01": 600, "agent02": 250},
  "by_operator": {"10086": 600, "10087": 250},
  "by_session": 37
}
```

| 字段 | 说明 |
|---|---|
| `by_endpoint` | 按端点计数（每个端点被调多少次） |
| `top_users` | 最活跃用户 TOP10（工号优先展示，无工号则账号） |
| `timeline` | 调用趋势曲线（**自适应粒度**：时间窗≤2天按小时、>2天按天；北京时间） |
| `by_operator` | 按工号计数（MCP 参数或 REST body 字段 `AGENT_USERNAME`） |
| `by_session` | distinct 会话数（MCP 参数或 REST body 字段 `AGENT_SESSION_ID`） |

### 3.3 GET /api/v1/telemetry/skill-usage — 底表导出（只读，供外部系统拉取）

**口径（scope 三选一）**：

| scope | 含义 | 行内容 |
|---|---|---|
| `call`（默认） | **调用级**：每次调用 1 行 | REST `POST /md`、`POST /domains`、`POST /search` 各 1 行 + MCP get_md/get_domains/search_graph 3 工具（及 legacy 兼容期三工具）每调用 1 行；含 params/result（search_files 两端点暂不在此口径，见 §3.2） |
| `object` | **对象级**细粒度：每取一个对象 1 行 | get_md / get_domains / REST 取用时按对象拆行（热榜统计同源）；无 params/result（搜索无对象级行） |
| `all` | 两类全含 | — |

**入参**：`scope`、`since`（游标，首轮留空，之后原样回传 next_since）、`limit`（1~10000 默认 1000）、
`start` / `end`（时间窗，纯日期=当天起止；end 翻页全程生效）。

**出参**：`{events:[{ts, caller, endpoint, obj_id, obj_type, user, operator,
session_id, level, params?, result?}], next_since, has_more}`（ts 升序；caller 恒为
skill/mcp——REST Agent=skill、MCP=mcp；网页端浏览不打点）。

```bash
# 拉某时间段的调用级底表（翻页直到 has_more=false，next_since 中 + 编码 %2B、| 编码 %7C）
curl -s "http://IP/api/v1/telemetry/skill-usage?scope=call&start=2026-09-01&end=2026-09-02&limit=1000" -H "X-API-Key: KEY"
curl -s "http://IP/api/v1/telemetry/skill-usage?scope=call&since=<上批next_since>&start=2026-09-01&end=2026-09-02&limit=1000" -H "X-API-Key: KEY"
# 对象级细粒度单独导出
curl -s "http://IP/api/v1/telemetry/skill-usage?scope=object&start=2026-09-01&end=2026-09-02&limit=1000" -H "X-API-Key: KEY"
```

### 3.4 GET /api/v1/telemetry/usage — 底表表格（运维页用）

时间**倒序** + 服务端分页 + 筛选：`scope`（call/object/all）、`start`/`end`、`endpoint`
（逗号分隔多选，含 `/search` 与 `mcp:search_graph`）、`q`（账号/工号子串）、`page`、
`size`（≤200 默认 50）。返回 `{rows, total}`，行结构同 3.3。

## 附录

### A. 对象 ID 格式

| 类别 | 段数 | 格式 | 示例 | version |
|---|---|---|---|---|
| 跨 NF 类（业务层） | 2 段 | `{Type}@{slug}` | `BusinessDomain@business-awareness`、`NetworkScenario@charging` | 恒 `null` |
| NF 类（任务/特性/命令层） | 3 段 | `{nf}@{Type}@{name}` | `UDG@AtomTask@ADD URR`、`UDG@MMLCommand@ADD APN` | 非空（如 `20.15.2`） |

> `name` 可含空格（如 `ADD URR`），ID 原样保留，整体作为一个字符串传入。

### B. 典型下钻链（沿 `[[ID]]` 引用逐层取）

```
get_domains                → 全部业务域 md（references 已提取）→ 锁定业务域
get_md {场景 id}            → 场景 md（决策点路由表） → 锁定场景
get_md {方案 id}            → 方案 md                → 锁定方案
get_md {task ids}          → FeatureTask/CompoundTask/AtomTask
get_md {特性/命令 ids}      → Feature / MMLCommand（按需；CommandParameter=参数权威）
```

每读一个 md，用 `references` 字段（或正则 `\[\[([^\]]+)\]\]` 提取）判断相关性后，
把相关的 ID 收集进下一批，再次 `get_md`，循环至所需知识齐备。
不知道 ID 时用 `search_graph`（多关键词 terms + match=any）定位候选。

### C. 错误处理

- HTTP 401：`X-API-Key` 缺失/无效（REST 图谱接口返回 `{"error":{"code":"UNAUTHENTICATED",...}}` envelope）→ 检查 KEY。
- HTTP 403：KEY 无 `skill` 权限（`PERMISSION_DENIED` envelope）→ 联系平台管理员开通。
- MCP 工具错误（isError=true）：`content[0].text` 为 `{"error":{code,message,...}}`
  JSON——`INVALID_ARGUMENT` 修正字段后重试；`RESULT_TOO_LARGE` 分批；
  `INVALID_FILTER` 从 available_values 选择；命中量过大已不报错（池触顶时
  `total_is_bounded=true`，加过滤词收窄或全量场景改用 `search_files`）；
  `INDEX_REBUILDING` 有界等待后重试；`INTERNAL_ERROR` 最多重试一次后报告。
- `get_md` 业务级错误（对象/版本不存在）：不整体失败，看该 id 条目的
  `ok:false` + `error_code`；按 `available_versions` 改版本重试，或用
  `search_graph` 重新定位，**不重试整批**。
