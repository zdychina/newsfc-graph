# 图谱接口（MCP，构建场景）

> 本 skill 对图谱**只读**：通过 Graph MCP 的 3 个公开工具查询命令层、特性层和已有的 Task / 业务层对象。
> 写入不走接口，而是产出 md 资产包，经平台「上传」导入（SKILL §4 P8）。
> 旧工具 `search_objects` / `search_md` / `get_object` 已废弃，**不要使用**。禁止用 curl / REST 绕过 MCP。

---

## 1. 调用上下文（每次调用必传）

| MCP 参数 | 值来源 | 规则 |
|---|---|---|
| `AGENT_USERNAME` | 环境变量 `_AGENT_USERNAME` | 工号；非空，不超过 64 字符 |
| `AGENT_SESSION_ID` | 环境变量 `_AGENT_SESSION_ID` | 会话 ID；非空，不超过 128 字符 |

这两个参数只用于统计归因，不得臆造，也不得省略。环境变量缺失时向用户索取。传入未知参数会被拒绝（`INVALID_ARGUMENT`）。

---

## 2. 三个工具

| 工具 | 用途 | 要点 |
|---|---|---|
| `get_domains` | 全部业务域的完整 md + `references` | P0 调一次，P2 和 P6 都复用这份结果 |
| `search_graph` | 按关键词统一搜索元数据和正文，返回候选 | **snippet 不是依据**；选定候选后必须 `get_md` |
| `get_md` | 按 ID 批量取完整 md（1~100 个，建议每批 5~20 个） | 权威原文的唯一来源；`references` 列出全文中的 `[[ID]]` |

`search_graph` 参数：`terms`（1~10 项，每项是一个字面词或短语，`"ADD URR"` 是一个短语）、`match`（默认 `any`；需要收窄时用 `all`）、过滤条件 `layer`（`命令层/特性层/任务层/业务层`）、`type`、`nf`、`version`、`domain`、`scenario`，以及 `page` / `size`（≤50）。不确定的过滤条件不要传，先看返回的 `facets` 再收窄。

`get_md` 参数：`ids`、可选的 `version`（不传则每个 ID 取最新版本）。单个 ID 失败（`ok:false`）不影响同批其他 ID，**不要重试整批**。

---

## 3. 错误处理

| 错误 | 处理 |
|---|---|
| 工具不可见 / 连接失败 / 401 / 403 | 立即停止，报告缺少图谱依赖 |
| `INVALID_ARGUMENT` | 修正参数（常见原因：漏传归因字段、拼错字段名）后重试 |
| `INVALID_FILTER(_COMBINATION)` | 从 `details.available_values` 中选值，或去掉该过滤条件 |
| `SEARCH_TOO_BROAD` | 加上 `nf` / `type` / `layer` 过滤后重试 |
| `RESULT_TOO_LARGE` | 把 `get_md` 拆成更小的批次 |
| `INDEX_REBUILDING` | 稍等后重试（retryable） |
| `get_md` 单项 `OBJECT_NOT_FOUND` | 这是一个**结论**（对象不存在），记入映射表，不是故障 |
| `get_md` 单项 `VERSION_NOT_FOUND` | 查看 `available_versions`，按需改版本 |
| `INTERNAL_ERROR` | 最多重试一次，仍失败则报告 |

## 4. 构建场景查询配方

> 下列配方是 P2 映射和 P5/P6 复用判定的标准做法。每次调用的结论都要记进 `_work/02-配置单元与映射.md`（写明调用了什么、得到什么、结论是什么），供审查复核。

### 4.1 命令存在性 + 参数定义

```
get_md(ids=["UNC@MMLCommand@ADD PNFPROFILE", "UNC@MMLCommand@SET ROAMCOMMPLCY", ...])
```

- 返回的 `version` 就是本批采用的命令版本，记入映射表。
- 读 md 中 CommandParameter 段的参数名、类型、枚举、必选与否、联动关系。**参数合法性只以这里为准**。
- `OBJECT_NOT_FOUND` → 用 `search_graph(terms=["ROAMCOMMPLCY"], type="MMLCommand", nf="UNC")` 找改名或近似命令；仍找不到，记为“版本差异：命令不存在”。

### 4.2 License 码 → 特性（最强映射信号）

```
search_graph(terms=["LKV2SAIRA01"], type="License")
→ get_md([License ID]) → 读 `## 边` 的「对应特性」→ get_md([Feature ID])
```

也可以反向核对：Feature 概述的 `## 边` 中有「所需License」。两个方向一致 = 强证据。

### 4.3 特性名 / 章节主题 → 特性

```
search_graph(terms=["精准寻呼"], layer="特性层", nf="UNC")
search_graph(terms=["漫游", "SEPP"], match="all", type="Feature", nf="UNC")
```

命中 Feature 概述后 `get_md`，读特性定义，确认与文档章节讲的是同一件事。仅凭名字相近 = 中等证据。

### 4.4 命令指纹 → 特性

```
search_graph(terms=["SET NGPAGINGCTRL", "ADD NGPAGINGRULE"], match="any", type="Feature", nf="UNC")
```

特性文档正文里会写它用到的命令（特性层有「使用命令」边）。命中的常常是特性的**子文档**（激活、操作步骤等，ID 形如 `{nf}@Feature@{code}-{slug}`）：沿子文档的「属于特性」边回溯到概述，按概述统计。一个单元的多条命令都集中命中同一特性 = 中等证据；只命中一条 = 弱证据，必须标“待确认”。

### 4.5 读 Feature 文档簇

```
get_md(["UNC@Feature@{code}"])        → 概述；其 `## 边` 的「包含子文档」列出全部子文档 ID
get_md([子文档 ID ...])               → 激活 / 数据规划 / 操作步骤 / 约束类子文档
```

构建 FeatureTask 时必须读完所有与配置相关的子文档（激活、配置、数据规划、操作步骤、约束限制）；纯原理类子文档可以跳过，但要记录跳过了哪些。

### 4.6 已有 Task（复用候选）

```
get_md(["UNC@AtomTask@ADD PNFPROFILE", ...])               → 该命令的 atom 是否已建
get_md(["UNC@FeatureTask@{code}"])                          → 该特性的 FT 是否已建
search_graph(terms=["ADD SCTPLE","ADD NGAPLE","ADD SCTPPARA"], match="any", type="CompoundTask", nf="UNC")
                                                            → 复用候选 CT（命中多者靠前）
```

对 CT 候选必须 `get_md` 读取 YAML 中的 `command_set`，再计算 Jaccard（`构建方法.md` §3）。**不要只看 snippet 就下复用结论。**

### 4.7 已有业务层

```
get_domains()                                               → 全部 BD（P0 已取，直接复用）
get_md([NS ID ...])                                          → 读 NS 的决策点路由表和下游方案
search_graph(terms=["漫游"], layer="业务层")                  → 找相近的 NS / CS
```

### 4.8 缓存取回的原文（供脚本使用）

`get_md` 返回的 `md` 是完整原文。以下对象取回后，要把 `md` 原样写入 `_work/cache/`（文件名任意，建议 `{ID}.md`；脚本以 frontmatter 的 `id` 为准）：

- 本批语句和规划表中出现的每条配置类命令的 MMLCommand（`check_params.py` 用）；
- 拟复用、拟更新的平台既有 Task 对象（lint 闭包计入其编排的命令；更新时作为 diff 底稿）。

返回 `OBJECT_NOT_FOUND` 的 ID 逐行追加到 `_work/cache/_not_found.txt`。缓存只是原文副本，不做任何修改。

## 5. 复用查询的最低要求（铁律 7 的操作化）

| 要新建的对象 | 新建前至少完成的查询 |
|---|---|
| AtomTask | 对该 ID `get_md` 返回 `OBJECT_NOT_FOUND` |
| CompoundTask | §4.6 的 CT 搜索（用本步骤的全部命令作 terms），并对前 5 个候选 `get_md` 算 Jaccard |
| FeatureTask | 对 `{nf}@FeatureTask@{code}` `get_md` 返回 `OBJECT_NOT_FOUND` |
| BD / NS | 通读 `get_domains` 结果，并按主题做 `search_graph(layer=业务层)` |
| CS | 读目标 NS 的下游方案，并按主题做 `search_graph(type=ConfigurationSolution)` |

---

## 6. ID 格式速查

- NF 类（3 段）：`{nf}@{Type}@{local}`，如 `UNC@MMLCommand@ADD PNFPROFILE`、`UNC@AtomTask@ADD PNFPROFILE`、`UNC@Feature@WSFD-xxxxxx`。local 中的空格原样保留，整体作为一个字符串传入。
- 业务层（2 段）：`{Type}@{slug}`，如 `NetworkScenario@inter-plmn-roaming`。
- 特性子文档：`{nf}@Feature@{code}-{slug}`（以概述「包含子文档」边中给出的为准，不要自行拼接）。
