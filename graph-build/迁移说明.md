# 迁移说明：从《三层图谱构建规范》task/ + business/ 到 graph-build

> 给维护者看的变更对照（Agent 执行时不需要读）。旧规范版本 v0.14.1（task SKILL sop 0.19.0，business SKILL sop 0.1.0）。

## 前提变化

| 旧 | 新 |
|---|---|
| 命令层、特性层、Task 层资产都在本地 `三层图谱资产/`，Agent 读本地文件 | 命令层、特性层都在平台上；Agent 只通过 MCP 读取，**只产出** Task 层和业务层 |
| 输入固定为产品文档（Feature 文档簇为主） | 输入是用户提供的任意文档；平台上的 Feature 文档簇用于补全特性全貌 |
| 四个层包各自带 agent / check / SKILL / 字段 / 模板 / CR | 合并为一个 skill：SKILL + 5 个模块 + 模板 + 脚本 |

## 删除（过时或冗余）

| 旧内容 | 删除原因 |
|---|---|
| AtomTask 全量构建（1.3 万条命令）+ `collect_command_examples.py` + `_intermediates/atom-input/` | 改为按需构建：只建本批编排实际用到、且平台上缺失的 atom |
| CompoundTask 复用库 `_index.md` + `gen_compound_index.py` | 这个库实际不存在（旧 README 已列为主要卡点）；改为 `search_graph(type=CompoundTask)` + `get_md` 读取 `command_set` 算 Jaccard |
| Task 层「被引用于」反向回填 + `audit_compound_feature.py` 的 D3 反链一致性检查 | 平台 `in_edges` 可反查；回填需要改动被引用对象，而且容易出现声明与实际不一致（与 2026-08-18 取消 Feature→FT 回填的决策一致） |
| `handoff/` 22 份交接记录、UDG/UNC 批次计划、构建提示词 | 历史过程文件，旧 SKILL 已声明它们不作规范依据 |
| 多 Agent 并行 + 唯一集成 Agent 的集成协议 | 本 skill 一次处理一份文档，用单构建者 + 独立审查即可；更新既有对象的冲突通过修改清单控制 |
| 细分边标签（编排 compound / 编排 atom / 直接引用 atom）、CT 的上游 / 下游边 | 统一为「编排」；步骤先后由编排顺序表达（老数据兼容保留） |
| 旧规范自相矛盾之处：compound SKILL B.1 的 YAML 含 version、business SKILL 中 `Task/{nf}/{ver}/` 路径、`assets/business/` 路径 | 统一为：无 version、`{Type}/{nf}/`、`Business/{domain}/[{scenario}/]`（与平台 registry 一致） |
| 层包标准、演进机制、CR 流程（针对这两层） | 改由 skill 的 `metadata.version` 和 Git 历史管理 |

## 保留（核心方法论）

静态 / 动态拆分；三段 / 两段 ID；文件名 = ID；无版本；无证据段；边白名单与禁止指向 ConfigObject / License；调测剥离；DP / 约束不编号；时间线不可泛化；防假通用（场景差异回填到 CT，这是**正文内容**，不是反向边）；参数核对四种结论；B1–B4 闭包；Jaccard + 相位同义的复用判定；抽 CT 的下限（<3 条不同命令直接引 atom）；特性关系矩阵；License 码必须核实；foundation / draft 状态；独立审查与严重级。

## 新增

| 新增 | 原因 |
|---|---|
| P1 语料画像 + 配置单元切分 + F / D / N 三类单元 | 用户文档不按特性组织，大量章节（接口、软参、可靠性）不属于任何特性 |
| D 型单元 → CompoundTask，由 CS 直接编排（`复用步骤` / `复用命令`） | 不新增对象类型也能承载部署类配置 |
| 实体映射的信号强度分级（LKV > 特性名 > 命令指纹 > 语义） | 文档没有特性码时，映射是推断出来的，需要证据分级和 GATE 确认 |
| 版本差异处理（以平台最新版为准并登记） | 文档版本（如 20.13.2）与平台版本不一致 |
| CS 的 `operator` 字段 + `## 运营商规范` 段（强制项 / 推荐值 / 规划规则）+ 局点数据脱敏 | 运营商规范归入 CS，Task 层保持通用 |
| CS 的「配置编排」有序列表 | 部署类方案需要明确的执行顺序 |
| Atom 的 `### 引用约束` 子节 | 下游 `config-generation` 做参数引用校验依赖它；旧模板没有这一节 |
| P3 GATE（构建计划须用户确认） | 映射、业务层建模、运营商规范的归属都需要人来拍板 |
| 更新既有对象的保全规则 + 修改清单 | 增量复用平台上已有的资产 |
| `extract_corpus.py` / `lint_assets.py` / `pack_bundle.py` | 确定性抽取、结构与闭包校验、打包上传 |

## 平台侧待确认

1. 取消回填后，前端邻居图和 `get_md` 的 `references` 只含出边；Agent 或前端需要反查“谁引用了我”时，要确认平台展示或接口是否提供入边（`index.in_edges` 已有，但 MCP 公开工具没有暴露）。
2. 平台 registry 会保留 CS 新增的可选字段 `operator`（未知字段原样保留），前端暂时不按它分组。
3. ✅（config-generation 6.3.0 已支持，见其 `图谱导航.md` §3.1）**下游 `config-generation` 需要认识 CS 编排行语法**（v1.1.0 新增，`对象规范.md` §6）：展开 FT 时按「激活方法」行取步骤，并执行 `省略` / `后移` / `仅步骤` / `重复` / `增量`。否则会整块展开 FT（例如过早执行总开关步骤）。

## v1.1.0（2026-09-21）：本地 mock 试跑 + 独立审查后的通用化修订

以《中国移动AMF异网漫游配置规范》§5.8.6 为样例跑完 P0–P7，独立审查给出 31 个产物问题和 13 条 skill 缺陷。按“问题抽象成通用规则，不针对样例”的原则修订：

| 问题类别（审查编号） | 通用修订 |
|---|---|
| 条件注释的作用域读错，整段漏配（C1） | `extract_corpus.py` 输出逐语句作用域；`语料处理.md` §3.1 作用域规则；时间线改为语句级（`构建方法.md` §2）；P3 决策必须附原文行号 + 摘录 |
| 数据规划表中的变体被静默丢失（C2），lint 仍报 0（S1、S2） | 抽取“规划表孤立项”（命令级 + 参数级）；lint 闭包纳入规划表；命令必须落到 Task 才算覆盖；未入图清单只认行首条目；新增参数闭包（WARNING） |
| 成员 / 对应关系没有进入资产（C3） | `语料处理.md` §6：成员与对应关系是行为，写成 CS 清单；CS 模板新增“成员与对应关系”表 |
| 必选参数缺失、取值越界、写法不一致未登记（H6、H7、M12、M13、S7、S9） | 新增 `check_params.py`（缓存命令定义 → 机械比对）；统一规范化口径（只有能机械对应的写法才规范化）；新增“文档内冲突表” |
| CS 无法结构化引用 FT 的部分步骤（H2、S4） | `对象规范.md` §6 编排行语法（激活方法 / 省略 / 后移 / 仅步骤 / 重复 / 增量）；FT 激活方法行命名；lint 检查 |
| FT 与原文顺序不一致（H1、M10） | 编排顺序以时间线为准；同一 FT 被隔开时拆分引用；偏离原文顺序须注明依据 |
| 运营商取值写进 CT 基线（H5、M14、S13） | `构建方法.md` §3.1.1：CT 基线只写维度与 `<规划值>` |
| 复用对象未核对覆盖（H3、S11）；复用记录缺失（M4、S12） | P2 第 4 步：既有对象覆盖核对 + 复用记录表；被复用对象缓存到 `_work/cache/` |
| 解析异常静默吞掉（M7、S10） | `extract_corpus.py` 输出解析异常清单；代码块外的 MML 语句也抽取 |
| 引子计数过期（I1、S6） | 模板去掉计数；允许同步更新派生文本并登记 |
| lint 结果不可复现（I6、S3） | 文档写明 `--scope`；报告记录命令行 |
| 特性子文档命中（自查） | 命令指纹命中子文档时回溯到概述 |
| License 开关是否计入 CT 下限（自查） | 不计入，由 FT / CS 单独编排 |

回归结果：在样例上重跑新脚本，C1（逐语句作用域）、C2（规划表孤立 15 条命令 / 参数）、H2（CS 未写激活方法）、H6 / H7 / M12 / M13（参数核对）、M7（2 处解析异常）均被自动检出；修订前 lint 报告 0。
